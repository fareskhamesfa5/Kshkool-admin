KOSHKOOl ADMIN — PURPLE & BLACK
================================

محتويات الحزمة
- index.html: صفحة تسجيل دخول المشرف.
- dashboard.html: الصفحة الرئيسية للوحة الإدارة.
- css/admin.css: تصميم بنفسجي وأسود ومتوافق مع الهاتف.
- js/supabase.js: إعداد عميل Supabase (ضع الرابط والمفتاح العام فقط).
- js/login.js: يرسل اسم المستخدم والرقم التعريفي وكلمة المرور إلى Edge Function.
- js/dashboard.js: يتحقق من الجلسة والدور ويعرض عدد الطلاب.
- pages/: صفحات أقسام الطلاب والدروس والامتحانات والنتائج والإعلانات والمشرفين.
- supabase/admin-setup.sql: جدول أدوار الإدارة وسياسة قراءة الدور الشخصي.
- supabase/functions/admin-login/index.ts: وظيفة دخول آمنة مبدئية.

مهم جداً — قبل التشغيل
1) هذه نسخة تأسيسية للواجهة والربط، وليست لوحة إنتاج مكتملة.
2) لا تضع كلمة مرور أو service_role key في ملفات HTML أو JavaScript.
3) افتح js/supabase.js وضع SUPABASE_URL والمفتاح العام (publishable/anon) فقط.
4) راجع supabase/admin-setup.sql مع مخطط مشروعك الحالي قبل تشغيله.
5) انشر Edge Function باسم admin-login واضبط أسرارها من لوحة Supabase:
   SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, ALLOWED_ORIGIN.
6) أنشئ مستخدم Auth للمشرف الأول من وسيلة موثوقة، ثم أضف صفه في admin_roles
   من بيئة آمنة. لا تضع كلمات المرور في SQL ولا في GitHub.
7) لا تسمح بإنشاء أو حذف المشرفين من المتصفح مباشرة. أضف Edge Functions منفصلة
   للتحقق من دور owner وتنفيذ إدارة المشرفين بعد اختبارها.
8) يجب إضافة سياسات RLS لكل جدول فعلي (students/lessons/exams/results/announcements)
   وفق مخططك. إخفاء رابط من الواجهة لا يعتبر حماية.
9) غيّر أي كلمة مرور سبق إرسالها داخل محادثة، ولا تعِد استخدامها.

ملاحظة عن الصلاحيات
- role = owner: الدور المقصود للمشرف الرئيسي.
- role = admin: مشرف تشغيل لا يملك صلاحية إدارة المشرفين.
- هذا التقسيم في الواجهة وحده غير كافٍ؛ يجب فرضه داخل Edge Functions وRLS.

التشغيل المحلي
يمكن فتح الواجهة عبر خادم محلي بسيط بعد إعداد Supabase. فتح الملفات مباشرة قد يسبب
مشكلات في بعض إعدادات المتصفح أو استدعاءات Edge Functions.
